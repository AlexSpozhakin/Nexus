# Система уведомлений - Современный подход

## Обзор

Система уведомлений полностью переработана в соответствии со стандартами современных приложений (Slack, Discord, Asana, Linear).

## Ключевые принципы

### ✅ Пользователь НЕ получает уведомления о своих собственных действиях

Это главное правило современных приложений. Если вы:
- Создали задачу и назначили себя → уведомление НЕ придёт
- Изменили статус своей задачи → уведомление НЕ придёт
- Оставили комментарий → уведомление НЕ придёт
- Удалили задачу → уведомление НЕ придёт

### 🎯 Уведомления получают только релевантные люди

Уведомления отправляются только тем, кто реально связан с задачей:
- **Создатель задачи** - всегда получает уведомления об изменениях
- **Assignees (Исполнители)** - получают уведомления о статусе и комментариях
- **Owners (Владельцы)** - получают все уведомления по задаче
- **Watchers (Наблюдатели)** - получают уведомления о важных изменениях

### 🚫 Никаких дублирующих уведомлений

Если пользователь одновременно является создателем и исполнителем задачи - он получит только ОДНО уведомление, а не два.

## Типы уведомлений

### 1. Task Assigned (Назначение на задачу)
**Кто получает:**
- Новый исполнитель (assignee)
- Owners и Watchers задачи

**Кто НЕ получает:**
- Тот, кто назначил (даже если назначил себя)

**Пример:**
```
John назначает задачу "Fix bug" на Mary
✅ Mary получает: "John assigned you to task: Fix bug"
❌ John НЕ получает уведомление
```

### 2. Task Status Changed (Изменение статуса)
**Кто получает:**
- Создатель задачи
- Все исполнители (assignees)
- Owners и Watchers

**Кто НЕ получает:**
- Тот, кто изменил статус

**Пример:**
```
Mary меняет статус задачи "Fix bug" на "Done"
✅ John (создатель) получает: "Mary changed status of Fix bug to done"
✅ Bob (watcher) получает уведомление
❌ Mary НЕ получает уведомление о своём изменении
```

### 3. New Comment (Новый комментарий)
**Кто получает:**
- Создатель задачи
- Все исполнители
- Owners и Watchers

**Кто НЕ получает:**
- Автор комментария

**Пример:**
```
Bob комментирует задачу "Fix bug": "Great work!"
✅ John (создатель) получает уведомление
✅ Mary (assignee) получает уведомление
❌ Bob НЕ получает уведомление о своём комментарии
```

### 4. Task Deleted (Удаление задачи)
**Кто получает:**
- Создатель задачи
- Все исполнители

**Кто НЕ получает:**
- Тот, кто удалил задачу

**Пример:**
```
John удаляет задачу "Old task"
✅ Mary (assignee) получает: "John deleted task: Old task"
❌ John НЕ получает уведомление
```

## Технические детали

### Обновлённые методы уведомлений

Все методы теперь принимают ID автора действия:

```go
// До (неправильно):
NotifyTaskAssigned(assigneeID, taskTitle, assignerName)

// После (правильно):
NotifyTaskAssigned(assigneeID, taskTitle, assignerName, assignerID)
```

### Автоматическая фильтрация

Каждый метод уведомлений автоматически проверяет:
```go
if userID == actionAuthorID {
    return // Не отправляем уведомление
}
```

### Новая функция для умных уведомлений

Добавлена `NotifyTaskRelevantUsers()` для продвинутой фильтрации:
- Автоматически исключает автора действия
- Отправляет уведомления на основе ролей
- Предотвращает дубликаты

## Примеры использования

### Создание задачи с назначением
```go
// Пользователь создаёт задачу и назначает на кого-то
if task.AssigneeID != nil && h.notificationService != nil {
    creator, _ := h.userRepo.GetByID(userID)
    creatorName := creator.Username

    // Автоматически не отправит уведомление, если userID == task.AssigneeID
    h.notificationService.NotifyTaskAssigned(
        *task.AssigneeID,
        task.Title,
        creatorName,
        userID, // ID автора действия
    )
}
```

### Изменение статуса задачи
```go
// Пользователь меняет статус задачи
if oldTask.Status != req.Status {
    // Уведомляем создателя (автоматически пропускается, если это он сам)
    h.notificationService.NotifyTaskStatusChanged(
        task.CreatorID,
        task.Title,
        req.Status,
        changerName,
        userID, // Автоматически исключается
    )

    // Уведомляем исполнителя (автоматически пропускается, если это он сам)
    if task.AssigneeID != nil {
        h.notificationService.NotifyTaskStatusChanged(
            *task.AssigneeID,
            task.Title,
            req.Status,
            changerName,
            userID, // Автоматически исключается
        )
    }
}
```

## Преимущества новой системы

### ✨ Для пользователей
- Не получают спам-уведомления о своих действиях
- Видят только релевантные уведомления
- Лучший UX, как в профессиональных приложениях

### 🔧 Для разработчиков
- Простая и понятная логика
- Автоматическая фильтрация
- Меньше багов
- Легко расширяемая система

### 🎯 Для бизнеса
- Соответствие современным стандартам
- Повышение удовлетворённости пользователей
- Профессиональный имидж продукта
