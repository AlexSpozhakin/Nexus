# Схема работы системы уведомлений

## До исправления (проблемная версия) ❌

```
Сценарий: John создаёт задачу и назначает себя

┌─────────────────────────────────────────────────────────┐
│ John: Создаёт задачу "Fix Bug" и назначает на себя     │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐
│ Backend: NotifyTaskAssigned(John, "Fix Bug", "John")   │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐
│ ❌ ПРОБЛЕМА: John получает уведомление:                 │
│ "John assigned you to task: Fix Bug"                   │
│                                                         │
│ Это бессмысленно - он сам себя назначил!               │
└─────────────────────────────────────────────────────────┘
```

## После исправления (правильная версия) ✅

```
Сценарий 1: John создаёт задачу и назначает себя

┌─────────────────────────────────────────────────────────┐
│ John: Создаёт задачу "Fix Bug" и назначает на себя     │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐
│ Backend: NotifyTaskAssigned(                           │
│   assigneeID: John,                                    │
│   taskTitle: "Fix Bug",                                │
│   assignerName: "John",                                │
│   assignerID: John  ← Новый параметр!                  │
│ )                                                      │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐
│ Проверка: assigneeID == assignerID?                    │
│ John == John? → ДА!                                    │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐
│ ✅ return; // Уведомление НЕ отправляется!              │
│                                                         │
│ John НЕ получает бессмысленное уведомление             │
└─────────────────────────────────────────────────────────┘
```

```
Сценарий 2: Mary назначает задачу на John

┌─────────────────────────────────────────────────────────┐
│ Mary: Создаёт задачу "Review PR" и назначает на John   │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐
│ Backend: NotifyTaskAssigned(                           │
│   assigneeID: John,                                    │
│   taskTitle: "Review PR",                              │
│   assignerName: "Mary",                                │
│   assignerID: Mary  ← ID автора                        │
│ )                                                      │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐
│ Проверка: assigneeID == assignerID?                    │
│ John == Mary? → НЕТ!                                   │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐
│ ✅ Отправляем уведомление!                              │
│                                                         │
│ John получает:                                         │
│ "Mary assigned you to task: Review PR"                │
│                                                         │
│ Mary НЕ получает уведомление (она автор действия)      │
└─────────────────────────────────────────────────────────┘
```

┌─────────────────────────────────────────────────────────┐

                        ↓

│ Mary == Bob? → НЕТ!                                    │
│ ✅ Mary получает уведомление                            │
└─────────────────────────────────────────────────────────┘

                        ↓

┌─────────────────────────────────────────────────────────┐
│ Backend: Уведомляем assignee                           │

│   userID: John,         ← Assignee                     │
│   commenterID: Bob                                     │
│ )                                                      │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐

## Умная фильтрация дубликатов

```
Сценарий: Mary создаёт задачу и назначает себя же

┌─────────────────────────────────────────────────────────┐
│ Mary - одновременно:                                   │
│ 1. Создатель задачи (CreatorID: Mary)                 │
│ 2. Assignee (AssigneeID: Mary)                         │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐
│ Backend: Уведомляем создателя                          │
│ Mary == Mary (автор действия)? → ДА!                   │
│ ❌ Уведомление НЕ отправляется                          │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐
│ Backend: Уведомляем assignee                           │
│ Mary == Mary (автор действия)? → ДА!                   │
│ ❌ Уведомление НЕ отправляется                          │
└─────────────────────────────────────────────────────────┘

Результат: Mary НЕ получает никаких уведомлений
(она создала задачу для себя - зачем ей уведомление?)
```

## Сравнение подходов

### ❌ Старый подход (наивный)
```go
// Плохо: просто отправляем всем
if task.CreatorID != userID {
    notify(task.CreatorID)
}
if task.AssigneeID != nil && *task.AssigneeID != userID {
    notify(*task.AssigneeID)
}
// Проблемы:
// 1. Много if-условий
// 2. Легко забыть проверку
// 3. Код сложно читать
```

### ✅ Новый подход (профессиональный)
```go
// Хорошо: фильтрация встроена в метод
h.notificationService.NotifyTaskStatusChanged(
    task.CreatorID,
    task.Title,
    newStatus,
    changerName,
    userID, // Автоматически исключается!
)
// Преимущества:
// 1. Чистый код
// 2. Невозможно забыть фильтрацию
// 3. Единообразие во всём приложении
```

## Ключевые улучшения

### 1. Автоматическая фильтрация
Вместо проверок `if userID != actionAuthorID` в каждом месте -
фильтрация встроена в сами методы уведомлений.

### 2. Невозможно ошибиться
Разработчик не может забыть добавить проверку -
она происходит автоматически.

### 3. Чистый код
Код handlers остаётся простым и читаемым,
вся логика фильтрации инкапсулирована в NotificationService.

### 4. Единообразие
Все уведомления работают одинаково -
нет разных подходов в разных местах.

### 5. Легко тестировать
Логику фильтрации можно протестировать в одном месте,
а не искать по всему коду.
